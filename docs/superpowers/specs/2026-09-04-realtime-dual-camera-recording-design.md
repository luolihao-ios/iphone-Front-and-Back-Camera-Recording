# 实时双摄合成录制设计

## 目标

将同框之外从“分别录制前、后两个原始视频，停止后导出合成”的架构，改为“录制期间实时合成前后摄画面并直接写入唯一最终视频”。

用户停止录制后，应用只需完成正在写入的最终文件，不再对整段素材进行二次合成导出。针对一分钟至两分钟的常见录制长度，停止到可保存的时间应显著短于当前方案，并接近系统相机的文件收尾体验。

## 范围

### 保留

- 前后摄像头同时预览与录制。
- 画中画、上下分屏两种布局。
- 录制前选择主摄像头；前置画面镜像。
- 画中画副画面位于右上角，圆角样式与录制预览保持一致。
- 麦克风音频写入最终合成视频。
- 停止时的开始、结束提示音不写进录制文件。
- 自动保存到照片图库、最近视频缩略图和全屏查看。

### 移除

- 前摄独立视频和后摄独立视频的录制、临时文件与保存选项。
- `VideoComposer` 的停录后整段视频导出职责。
- `RecordingFiles`、`SaveSelection` 中针对多文件保存的模型。

## 架构

### 实时合成器

新增一个实时合成录制器，拥有一个 `AVAssetWriter`、一个视频输入、一个音频输入，以及用于写入合成视频像素缓冲区的适配器。

录制开始时，它创建一个唯一的临时 `.mov` 文件和固定的 1080×1920 输出画布。前后摄视频输出仍由 `AVCaptureMultiCamSession` 驱动；每组时间相近的视频帧交给实时合成器。

实时合成器使用 GPU 支持的 Core Image/Metal 渲染上下两个输入帧：

- 画中画：主画面 `aspect-fill` 至完整画布；副画面 `aspect-fill` 至右上角的固定矩形，并实时施加圆角遮罩。
- 上下分屏：两路画面分别裁切、缩放至画布上半与下半，两个目标区域均为 1080×960。
- 前置帧在进入合成器前保持镜像变换。

合成结果直接写入唯一视频输入。音频样本直接写入同一写入器的音频输入。

### 同步与背压

以主画面时间戳作为输出节奏。每个主画面帧使用最近且不晚于该时间点的副画面帧进行合成；尚未获得副画面首帧前不写入视频。这样可以避免等待单个延迟帧而造成录制阻塞。

当写入器或像素缓冲区池暂时无法接收数据时，丢弃当前过期帧并继续采集最新帧。应用绝不在相机采样队列等待磁盘或 GPU；优先保证界面和会话可响应。

### 停止与保存

点击停止时：

1. 立即停止接受新的录制样本，关闭音频写入。
2. 标记最终视频和音频输入结束。
3. 等待唯一 `AVAssetWriter` 完成写入。
4. 成功后将该文件写入照片图库，刷新缩略图；失败则显示明确错误。

不会创建前、后原始 `.mov`，也不会启动 `AVAssetExportSession` 做整段重绘或导出。

## 界面与设置

- 录制中的处理提示改为白底黑字“正在完成录制…”。
- 设置页删除“保存到照片图库”下的三个开关，改为“录制完成后自动保存合成视频”的静态说明。
- 保存过程不使用确认弹窗。短录制仅在写入完成期间显示处理提示。

## 错误处理

- 无法创建写入器、像素缓冲区或缺少首帧：停止录制并显示“无法开始视频写入，请重试”。
- 写入器失败：删除临时文件，显示“视频写入失败，请重试”。
- 照片图库保存失败：保留最终临时文件至本次会话结束，并显示“保存失败”。
- 性能压力：丢弃过期帧，不阻塞采样队列、不黑屏、不持续卡在处理状态。

## 验证

### 自动化

- 为输出布局尺寸、唯一输出文件策略、停止状态转换和移除独立保存选项添加回归测试。
- 在 GitHub Actions 运行设备构建、iPhone Simulator 单元测试及 IPA 打包。

### 真机验收

- 画中画与上下分屏各录制 10 秒、1 分钟、2 分钟。
- 确认停止后不会进行与视频时长成比例的二次导出等待。
- 确认成片布局、右上角圆角画中画、前置镜像、音频与预览一致。
- 确认长视频不会黑屏、崩溃或卡在“正在完成录制…”。
