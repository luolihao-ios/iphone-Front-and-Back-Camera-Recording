# 全屏相机与保存动效修复计划

> 执行方式：在当前隔离工作树连续实施，使用 executing-plans 流程；先补测试，再修复，再进行独立代码复核。

## 目标与约束

- 恢复照片、视频保存成功后向相册按钮吸入的动效，不更换成简单缩略图缩放。
- 原生支持 iPhone 和 iPad，根据实际窗口与安全区域调整布局，不使用固定手机画布或兼容模式黑边。
- iPhone Duo 展开、收起及旋转时重新布局；真正使用 Duo 全屏需要 iOS 27.1 SDK，不能用修改版本号假装满足要求。
- 不改变实时合成写入、相册保存、录音和设置页检查更新的既有流程。
- 项目文档使用中文；不在没有实测证据时声称真机适配通过。

## 设计与根因调查

当前工程仅声明设备族 1、只支持竖屏；原生 iPad 支持和旋转均未启用。界面已采用尺寸测量，但菜单及底部控件仍按手机竖屏预留空间。圆形画中画在横屏和展开窗口下会超出短边，录制中改变窗口比例会将圆拉伸。

保存动效依赖插入视图后 Task.yield 再修改终值。yield 不是一次屏幕绘制，无法保证初始帧显示。改用视图挂载后的显示时钟逐帧计算进度；相册目标保持测量缓存并在每次播放冻结。日志记录挂载、首帧、中间帧、完成及无目标跳过原因。

## 实施任务

- [ ] 1. 添加横屏大圆越界、窗口变化圆形变形、异常窗口编码尺寸的回归测试；在 CI 观察旧实现失败。
- [ ] 2. 保存动效改用挂载后启动的显示时钟，完成回调更新相册缩略图；添加时钟与显示集成测试。
- [ ] 3. 启用 iPad 原生设备族及各方向，按窗口计算控件宽度、菜单可用高度、安全区域；修复圆形边界及编码画布约束。
- [ ] 4. 按窗口所属场景方向配置采集连接；录制期间保持方向固定，结束后恢复当前场景方向；发现真实可用前后摄组合，包括 iPad 超广角前摄。
- [ ] 5. 构建使用环境中最新可用 Xcode，记录 SDK 版本及 Duo 全屏能力，运行 iPhone 与 iPad 模拟器测试；不具备 27.1 时明确标注 Duo 构建限制。
- [ ] 6. 独立复核、修复重要问题、检查所有差异，提交并触发构建；仅等待 GitHub 构建时停止轮询。

## 重点复核

1. 保存期间隐藏相册按钮导致目标变零，播放首帧被合并，旋转导致旧动画飞出窗口。
2. 横屏窄窗口中菜单设置入口被遮挡，底部控件与右侧菜单重叠。
3. 圆形在横屏、展开窗口及录制时调整窗口后变椭圆或越界。
4. 相机输出方向切换混入旧样本、前摄镜像或实时文件写入退化。
5. CI 未安装所需 SDK、没有 iPad 模拟器或真实硬件不支持所选双摄组合。

## 验证记录

- 基线：a61b3b9，1.0.13 (4)。工作树干净。
- 本机为 Windows，没有 Swift/Xcode，iOS 构建与 XCTest 交由 GitHub macOS CI；这不等于已完成真机测试。
- Apple 官方全屏要求：https://developer.apple.com/videos/play/tech-talks/111461/
- GitHub 的 macOS 26 镜像没有 Xcode 27.1，但另一个 `xcode-27` 镜像的 20261023.0307.1 版本已有 Xcode 27.1（27A9275）、iOS 27.1 SDK 与 Duo 模拟器。因此两个工作流都改为这个镜像并明确选择 27.1，不使用更高版本 RC。
- 实现选择：窗口改变时预览始终铺满；文件的画布与相机方向在开始录制时固定，结束后应用待处理方向，以免同一个文件混入不同方向/尺寸。
- 动效由已挂载视图的 TimelineView 驱动；回调完成后更新相册缩略图，不依赖父任务的 yield 或一次隐式动画提交。
- 回归基线 CI：40310211249，44 项测试中新增的 3 项按预期失败：横屏圆越界、展开后圆宽 286.72 高 120.96、窄长窗口编码高度达到 8640。其他 41 项通过。
- 独立复核发现播放中旋转会保留旧目标坐标；已增加窗口变化时立即结束动效、提交缩略图的处理，避免飞出屏幕。
- iPad 图标使用同一张既有 1024 像素原图交由资源编译器生成全平台尺寸，不修改图标内容。
