# 日志可见性与录像反馈排查

## 已证实的问题

用户在 iPhone 的“文件”中找不到同框之外目录。解包构建 1.0.13 (5) 的实际 IPA（CI 40311901334）后读取 Info.plist，得到：

- UIFileSharingEnabled：缺失。
- LSSupportsOpeningDocumentsInPlace：布尔值 true。

因此工程中的 INFOPLIST_KEY_UIFileSharingEnabled 并未进入成包，不能据此声称用户能在“文件”中访问日志。旧日志初始化还会覆盖上一会话，写入错误被 try? 静默忽略；设置页也没有任何查看或导出入口。

录像动效未显示仍在排查。当前只能确认动效存在“提取缩略图返回 nil 即直接跳过”的分支，不能把这个潜在原因当作真机已证实根因。新建了从真实实时合成录制器完成写入、再立即生成动效缩略图的集成测试；CI 40355079575 的 iPhone 测试已通过，说明简单模拟器样例没有复现提图失败，不据此宣称真机问题解决。

## 本次修改

1. XcodeGen 明确生成 Info.plist 并写入文件共享两个布尔键，不再依赖未生效的构建变量。设备 Release 包与正式上传 archive 都增加 PlistBuddy 校验。
2. 设置页增加“诊断 → 查看／导出诊断日志”，可查看文本、刷新并通过系统分享面板导出真实 .log 文件。无需连接 Xcode，也无需先找到系统“文件”中的应用目录。
3. 日志自动创建 Documents，保留以前会话，标注版本和 SDK；导出与待写消息串行，确保导出的快照包含已提交的记录。写入或导出失败在诊断页显示，不生成虚假下载入口。
4. 补齐录像保存、提图请求与结果、动效无图跳过、相册目标测量以及动效结束原因日志。暂不凭猜测改写动效或录制架构。
5. 日志仅保存在本机，不采集图像、录音或面部数据，不自动上传。同步中文隐私说明。

## 验证与交付

- 新增回归测试：实际应用 Info.plist 共享键、新目录自动创建和导出、跨会话保留、存储失败可见。
- 安装包版本提升为 1.0.13 (6)，用于区分诊断版。
- 运行 iPhone、iPad、Duo 全部 XCTest 与设备编译；只有执行结果通过才声明验证通过。仅等待 CI 时按用户规则停止轮询。
- 本轮不擅自提交 App Store 审核，也不将日志问题修复表述为录像动效已修复。
- 独立只读复核未发现严重或重要阻断；指出临时写入失败后的普通成功写入会抹去失败状态。已改为先落盘恢复标记，再清除错误；增加通过真实文件变成目录再恢复的回归测试。
- 本机完成 YAML 语法与两个显式布尔键检查、git diff --check；不将这些静态检查当作 iOS 编译通过。
